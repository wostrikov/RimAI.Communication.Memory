# Посібник із реалізації Prompt Caching (кешування на боці моделі)

## ?? **Огляд**

**Prompt Caching** — це явна функція кешування, яку надають постачальники моделей ШІ (як-от OpenAI, DeepSeek, Google). Вона дає змогу кешувати повторювані префікси prompt на стороні моделі, завдяки чому:

- ? **Зниження витрат на 50%**: токени, знайдені в кеші, оплачуються за 50% ціни
- ? **Швидша відповідь**: обробка повторюваних токенів пропускається
- ? **Автоматичне керування**: модель автоматично підтримує кеш (термін дії — 5–10 хвилин)

---

## ?? **Основна ідея**

### Поточна структура prompt
```
完整prompt = 固定system指令 + 变化的记忆/常识 + 用户输入
```

### Оптимізована структура
```
system消息（可缓存） = 固定指令（如角色设定、规则）
user消息（不缓存） = 记忆注入 + 常识注入 + 用户对话
```

**Результат**:
- Фіксовані інструкції для кожного колоніста оплачуються лише під час першого виклику
- У наступних діалогах (протягом 5–10 хвилин) спрацьовує кеш, а витрати зменшуються на 50%

---

## ?? **План реалізації**

### Варіант 1: кеш OpenAI/DeepSeek

Змініть метод `BuildJsonRequest()` у `IndependentAISummarizer.cs`:

```csharp
// OpenAI: 在system消息中添加cache_control
sb.Append("{\"role\":\"system\",");
sb.Append("\"content\":\"" + systemPrompt + "\"");
sb.Append(",\"cache_control\":{\"type\":\"ephemeral\"}");  // ?? 关键
sb.Append("},");

// DeepSeek: 添加cache标记和全局开关
sb.Append(",\"cache\":true");  // 消息级别
sb.Append(",\"enable_prompt_cache\":true");  // 请求级别
```

### Варіант 2: Google Gemini Context Caching ? Додано

Google Gemini використовує механізм **Context Caching**, на відміну від OpenAI/DeepSeek:

```csharp
// Gemini: 在generationConfig中启用缓存
{
  "contents": [...],
  "generationConfig": {
    "temperature": 0.7,
    "maxOutputTokens": 200
  },
  "cachedContent": "projects/{project}/locations/{location}/cachedContents/{id}"
}
```

**Особливості кешування Gemini**:
- ? Підтримує кешування (Context Caching)
- ?? Спочатку потрібно створити об’єкт CachedContent (складніше)
- ?? Безкоштовна версія (AI Studio) має обмежені можливості кешування
- ?? У цьому проєкті кешування Gemini наразі не реалізується (висока складність, обмежена користь)

| **Економія** | **$0.35/день** | **$10.5/місяць** |

## ?? **Важливі зауваження**

### 1. Термін дії кешу
- OpenAI: 5–10 хвилин (автоматично спливає)
- DeepSeek: приблизно 10 хвилин
- Google Gemini: налаштовується (потрібен Vertex AI)
- **Рекомендація**: найкраще працює під час частих діалогів (наприклад, послідовних діалогів у грі)

### 2. Сумісність
- ? OpenAI GPT-4 Turbo, GPT-3.5 Turbo (підтримується автоматично)
- ? DeepSeek Chat, Coder (підтримується автоматично)
- ?? Google Gemini (підтримується, але реалізація складна; наразі цей проєкт не реалізує цю функцію)

### 3. Налагодження
Перегляньте інформацію про кеш у заголовках відповіді:
```
X-Cache-Control-Stats: hit=1, miss=0, token_savings=150
```

### 4. Найкращі практики
- Тримайте system prompt стислим (<500 токенів)
- Уникайте частого редагування вмісту system
- Пам’ять /ін’єкція загальних знань розміщується в повідомленні user

## ?? **Параметри конфігурації**

Перемикач уже додано до `RimTalkSettings.cs`:

```csharp
public bool enablePromptCaching = true;  // 启用Prompt Caching（默认开启）
```

У UI налаштувань (розділ конфігурації AI):
```
?? 启用Prompt Caching（降低50%费用）
```

**Увага**: цей параметр діє лише для OpenAI і DeepSeek; Google Gemini наразі не підтримується.
