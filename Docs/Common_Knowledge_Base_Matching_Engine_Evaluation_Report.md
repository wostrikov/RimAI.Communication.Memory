# Звіт про оцінювання рушія зіставлення бази загальних знань

## Резюме

**Висновок оцінювання**: **Не рекомендується** використовувати рушій вилучення ключових слів системи пам’яті (`SuperKeywordEngine`) як резервний варіант для бази загальних знань.

**Основні причини**:
1. ? Не вирішує головну поточну проблему (хибне спрацьовування назв навичок)
2. ? Підвищує складність системи, а користь обмежена
3. ? Знижує контрольованість і прозорість для користувача
4. ? Векторний пошук уже забезпечує краще семантичне зіставлення

## I. Порівняння поточної архітектури системи

### Система зіставлення бази загальних знань (Current)

**Метод**: пряме зіставлення тегів + векторне вдосконалення (необов’язково)

```
匹配流程：
1. 标签匹配（主要）
   - 使用 IndexOf 子字符串匹配
   - 支持 Any/All 模式
   - 匹配文本 = 对话内容 + Pawn基本信息 + Pawn技能（≥10级）

2. 向量匹配（补充）
   - 使用 Embedding API 计算语义相似度
   - 异步后台执行
   - 可选启用
```

**Особливості**:
- ? Простий і зрозумілий для користувача
- ? Повністю контрольовано, мітка — це саме те, що ви бачите
- ? Легко випадково активувати (короткі мітки, назви навичок)
- ? Векторний пошук забезпечує семантичне доповнення

### Зіставлення із системою пам’яті (Memory)

**Метод**: вилучення ключових слів + інтелектуальне оцінювання

```
匹配流程：
1. 关键词提取（SuperKeywordEngine）
   - TF-IDF 权重
   - BM25 评分
   - 停用词过滤
   - 位置权重
   - 长度权重

2. 智能评分（DynamicMemoryInjection）
   - 时间衰减
   - 重要性
   - 关键词匹配（Jaccard 相似度）
   - 关系加成
   - 层级加成
   - 场景权重（动态调整）
```

**Особливості**:
- ? Інтелектуально, враховує багатовимірні фактори
- ? Динамічні ваги адаптуються до ситуації
- ? Складно, важко передбачати й налагоджувати
- ? Слабкий контроль користувача

## 2. Основні проблеми бази знань про здоровий глузд

### Проблема 1: випадкове спрацьовування назви навички ? **Найсерйозніша**

**Явище**:
```
标签：[射击]
Pawn：张三（射击15级）
对话："今天天气不错"
匹配文本："今天天气不错 张三 女性 人类 工作狂 射击 近战 建造"
结果：? 匹配成功（误触！）
```

**SuperKeywordEngine Чи може це вирішити проблему?**
- ? **Ні**
- Причина: `BuildPawnInfoText` усе одно додаватиме назви навичок до тексту для зіставлення
- Механізм ключових слів витягне ключове слово «Стрільба»
- Мітка «Стрільба» усе одно успішно зіставлятиметься

**Єдине рішення**:
- Користувач використовує комбіновану мітку: `[规则-射击战斗,瞄准]`
- Або змінити `BuildPawnInfoText`, щоб не додавати назви навичок (але це вплине на коректні зіставлення)

### Проблема 2: хибне спрацьовування коротких міток

**Прояви**:
```
标签：[星]
对话："我们去火星探险"
结果：? 匹配（合理）

对话："今天是星期一"
结果：? 匹配（误触！）
```

**Чи може SuperKeywordEngine це виправити?**
- ?? **Частково**
- Механізм ключових слів відфільтровує низькоякісні слова з 1–2 символів
- Але якщо користувач задасть 3-символьну мітку «Тиждень», усе одно можливе хибне спрацьовування

**Компроміс**:
- Після введення механізму ключових слів короткі мітки автоматично ігноруватимуться
- Але користувачеві можуть бути потрібні короткі мітки (наприклад, імена людей або географічні назви)
- Знижує контроль користувача

## 3. Докладний аналіз SuperKeywordEngine

### Технічні характеристики 3.1

| Характеристика | Опис | Сценарій застосування |
|------|------|---------|
| Вага TF-IDF | Частота терміна — обернена частота документа | Пошук у пам’яті (велика кількість документів) |
| Оцінювання BM25 | Алгоритм найкращого збігу | Сценарії пошукових систем |
| Фільтрація стоп-слів | Фільтрує «的», «是» тощо | Аналіз китайських та англійських текстів |
| Вага позиції | Слова на початку важливіші | Витягування заголовків і резюме |
| Вага довжини | Довші слова важливіші | Розпізнавання власних назв |
| Нечіткий пошук | Толерантність до помилок (помилок написання) | Пошук із виправленням помилок |

### Переваги 3.2

? **Переваги в системі пам’яті**:
- Витягування ключової інформації з довгих текстів
- Оцінювання за кількома параметрами для підвищення релевантності
- Динамічні ваги для адаптації до різних сценаріїв (бій, спілкування, робота)
- Часове згасання, новіші спогади мають пріоритет

? **Технічні переваги**:
- Детермінований алгоритм (однакові вхідні дані → однаковий результат)
- Оптимізована продуктивність (<10 мс, повна синхронізація)
- Перевірений код (валідований у системі спогадів)

### 3.3 Недоліки (у сценарії бази загальних знань)

? **Чому це не підходить для бази загальних знань**:

1. **Невідповідність сценарію**
   - Спогади: велика кількість записів (сотні або тисячі), потрібне інтелектуальне сортування
   - Загальні знання: невелика кількість точних записів (десятки), потрібен точний збіг

2. **Різні очікування користувачів**
   - Спогади: автоматичне керування, користувача не цікавлять деталі
   - Загальні знання: створюються вручну, очікується точний контроль

3. **Різні предметні області**
   - Спогади: потрібно знаходити найрелевантніше серед величезного обсягу історичних даних
   - Здоровий глузд: певне правило потрібно активувати в конкретній ситуації

4. **Не вирішує основної проблеми**
   - Помилкове спрацьовування на назвах навичок: механізм ключових слів також витягуватиме назви навичок
   - Короткі мітки: хоч і дають змогу фільтрувати, але знижують гнучкість

## Чотири. Оцінювання альтернативних варіантів

### Варіант A: запровадити SuperKeywordEngine

**Реалізація**:
```csharp
// 在 CommonKnowledgeLibrary 中
private bool IsMatched(string text, CommonKnowledgeEntry entry)
{
    // 1. 提取匹配文本的关键词
    var contextKeywords = SuperKeywordEngine.ExtractKeywords(text, 20);
    var contextWords = contextKeywords.Select(kw => kw.Word).ToList();
    
    // 2. 提取标签关键词
    var tags = entry.GetTags();
    
    // 3. Jaccard 相似度匹配
    var intersection = tags.Intersect(contextWords).Count();
    var union = tags.Union(contextWords).Count();
    
    if (union == 0) return false;
    
    float similarity = (float)intersection / union;
    return similarity >= 0.3f; // 阈值
}
```

**Вплив**:
- ? Зменшує кількість помилкових спрацьовувань на деяких коротких мітках
- ? Підвищує складність (додається ще один параметр порога)
- ? Знижує передбачуваність (користувач не знає, чому збігу не відбулося)
- ? **Не вирішує проблему назв навичок**

### Варіант B: зберегти поточний стан + оптимізувати документацію

**Реалізація**:
- Зберегти поточний механізм зіставлення `IndexOf`
- Посилення навчання користувачів (довідкова документація)
- Надання прикладів найкращих практик

**Вплив**:
- ? Просто й зрозуміло
- ? Повний контроль
- ? Векторний пошук уже забезпечує семантичне доповнення
- ?? Користувачам потрібно дотримуватися правил тегування

### Варіант C: Покращення BuildPawnInfoText

**Реалізація**:
```csharp
// 不添加技能名到匹配文本
private string BuildPawnInfoText(Verse.Pawn pawn)
{
    var sb = new StringBuilder();
    sb.Append(pawn.Name.ToStringShort);
    sb.Append(" ");
    sb.Append(pawn.gender.GetLabel());
    sb.Append(" ");
    sb.Append(pawn.def.label);
    sb.Append(" ");
    
    // 只添加特性，不添加技能
    if (pawn.story?.traits != null)
    {
        foreach (var trait in pawn.story.traits.allTraits)
        {
            sb.Append(trait.def.label);
            sb.Append(" ");
        }
    }
    
    return sb.ToString();
}
```

**Вплив**:
- ? Повне усунення помилкових збігів назв навичок
- ? Зниження можливостей зіставлення (зіставлення за навичками буде неможливим)
- ? Може вплинути на обґрунтовані сценарії зіставлення

## Додаток: причина успіху SuperKeywordEngine у системі пам’яті

### Чому це підходить для системи пам’яті?

1. **Величезний обсяг даних**
   - Кількість записів пам’яті може сягати сотень і тисяч
   - Потрібне інтелектуальне сортування, щоб знаходити найрелевантніші

2. **Автоматичне керування**
   - Користувач не пише спогади вручну
   - Система автоматично записує та оцінює їх

3. **Часовий вимір має значення**
   - Нові спогади важливіші за старі
   - Часове згасання є ключовою вимогою

4. **Адаптація до різних сценаріїв**
   - У боях, спілкуванні, роботі тощо ваги відрізняються
   - Динамічне налаштування має велику цінність

### Чому це не підходить для бази загальних знань?

1. **Невеликий обсяг точних даних**
   - Записів загальних знань зазвичай кілька десятків
   - Потрібно точно контролювати кожен запис

2. **Написання вручну**
   - Користувач очікує: "що напишеш, те й спрацює"
   - Мітки мають бути інтуїтивно зрозумілими тригерами

3. **Часовий вимір не має значення**
   - Здоровий глузд — це постійне правило/передумова
   - Часове згасання не потрібне

4. **Сценарії фіксовані**
   - Кожному правилу здорового глузду відповідає чіткий сценарій
   - Динамічні ваги не потрібні
