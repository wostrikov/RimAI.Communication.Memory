# Звіт про виправлення помилки часових міток підсумків ELS

## ?? Опис помилки

**Проблема**: Під час щоденного підсумовування ELS і архівації CLPA створений підсумок/архівна пам’ять використовував поточну часову мітку, а не фактичну часову мітку узагальненої/архівованої пам’яті.

**Вплив**: 
- ШІ вважав, що події з підсумку відбулися «сьогодні», а не «вчора» чи «кілька днів тому»
- Порушувалася логіка сприйняття часу ШІ
- Виникала плутанина в часовій шкалі (наприклад: «сьогодні я 5 разів розмовляв із Bob» — насправді це підсумок учорашніх спогадів)

**Серйозність**: ?? **Висока** — впливає на точність сприйняття часу ШІ

## ?? Першопричина

### Проблемний код 1: `FourLayerMemoryComp.cs` — `DailySummarization()`

```csharp
// ? 错误：使用当前时间作为总结的时间戳
var summaryEntry = new MemoryEntry(
    content: simpleSummary,
    type: typeGroup.Key,
    layer: MemoryLayer.EventLog,
    importance: memories.Average(m => m.importance) + 0.2f
);
// MemoryEntry构造函数会自动设置 timestamp = Find.TickManager.TicksGame
// 这导致总结的时间戳是第二天（总结时）的时间
```

### Проблемний код 2: `MemoryManager.cs` — `CheckArchiveInterval()`

```csharp
// ? 错误：归档记忆也使用当前时间戳
var archiveEntry = new MemoryEntry(
    content: archiveSummary,
    type: typeGroup.Key,
    layer: MemoryLayer.Archive,
    importance: memories.Average(m => m.importance) + 0.3f
);
// 同样的问题：timestamp被设置为当前时间
```

## ? Спосіб виправлення

**Основна ідея**: використовувати **найранішу часову мітку** в узагальненій/архівованій пам’яті як часову мітку запису підсумку/архіву

### Виправлення 1: `DailySummarization()` і `ManualSummarization()`

```csharp
// ? 正确：使用被总结记忆中最早的时间戳
var memories = typeGroup.ToList();
int earliestTimestamp = memories.Min(m => m.timestamp);

var summaryEntry = new MemoryEntry(
    content: simpleSummary,
    type: typeGroup.Key,
    layer: MemoryLayer.EventLog,
    importance: memories.Average(m => m.importance) + 0.2f
);

// ? 修复：覆盖默认的timestamp
summaryEntry.timestamp = earliestTimestamp;
```

**Пояснення логіки**:
- Якщо пам’ять SCM сформована в проміжку від 8:00 учора до 7:00 сьогодні
- Найраніший спогад — учора о 8:00 (timestamp = T1)
- Підсумок має представляти часовий проміжок «від учора до сьогодні»
- Використати найраніший timestamp (T1), щоб AI знав, що ця пам’ять «почалася вчора»

---

### Виправлення 2: `CheckArchiveInterval()` (архівування CLPA)

```csharp
// ? 正确：归档时也使用最早的timestamp
var memories = typeGroup.ToList();
int earliestTimestamp = memories.Min(m => m.timestamp);

var archiveEntry = new MemoryEntry(

    type: typeGroup.Key,

);

// ? 修复：覆盖默认的timestamp
archiveEntry.timestamp = earliestTimestamp;
```

## ?? Перевірка

### Сценарій 1: автоматичний щоденний підсумок опівночі

**Кроки тестування**:
1. Ігровий день 5, 23:00 — у пішака є 5 спогадів SCM (їхні часові мітки припадають на різні моменти дня 5)
2. Ігровий день 6, 0:00 — запускається щоденний підсумок
3. Перевірити timestamp підсумкових спогадів ELS

**До виправлення**:
```
ELS总结: timestamp = Day 6, 0:00 (总结触发时间)
AI认为: "今天我和Bob对话了5次" (错误！)
```

**Після виправлення**:
```
ELS总结: timestamp = Day 5, 8:00 (最早SCM记忆的时间)
AI认为: "昨天我和Bob对话了5次" (正确！)
MemoryEntry.TimeAgoString = "昨天"
```

### Сценарій 2: автоматичне архівування CLPA через 7 днів

**Кроки тестування**:
1. День 14 у грі — у Pawn є 20 спогадів ELS (часові мітки між 7-м і 14-м днем)
2. Запустити 7-денне архівування
3. Перевірити timestamp архівованих спогадів CLPA

**До виправлення**:
```
CLPA归档: timestamp = Day 14 (归档触发时间)
AI认为: "最近（15-30天）一直在做XX工作" (时间感知错误)
```

**Після виправлення**:
```
CLPA归档: timestamp = Day 7 (最早ELS记忆的时间)
AI认为: "上周（7-15天）一直在做XX工作" (正确)
MemoryEntry.TimeAgoString = "上周"
```

## ?? Основні моменти перевірки коду

### Чому використовується `Min()`, а не `Max()`?

**Фактори, що враховувалися**:

1. **Семантична точність**:
   - Підсумок представляє події за **певний період часу**
   - Найдавніший спогад представляє **початок** цього періоду
   - Користувача більше цікавить, "коли це почало відбуватися"

2. **Часове сприйняття ШІ**:
   - "Учора я ходив добувати руду" — користувач очікує, що ШІ зрозуміє: ця діяльність почалася вчора
   - Якщо використати Max(), ШІ вважатиме, що це діяльність сьогоднішнього дня (оскільки останній спогад може бути близьким до півночі)

3. **Рядок часу, що минув**:
   - `Age = Find.TickManager.TicksGame - timestamp`
   - Використання Min() збільшує Age → TimeAgoString стає "давнішим" → результат точніший

**Приклад**:
```
SCM记忆:
- Memory 1: Day 5, 8:00  ← Min (最早)
- Memory 2: Day 5, 12:00
- Memory 3: Day 5, 20:00
- Memory 4: Day 5, 23:50 ← Max (最晚)

总结时间: Day 6, 0:00

Min策略:
timestamp = Day 5, 8:00
Age = ~16小时
TimeAgoString = "昨天" ?

Max策略:
timestamp = Day 5, 23:50
Age = ~10分钟
TimeAgoString = "刚才" ? (错误！)
```
