# Посібник із використання інструмента тестування міток

## Огляд функцій

**Інструмент тестування тегів** — це окреме спливне вікно, що допомагає перевірити, чи правильно теги відповідають вмісту діалогів.

## Розташування

**Інтерфейс бази знань** → **Бічна панель ліворуч** → кнопка **?? Тестування тегів** (світло-зелена)

Після натискання відкриється окреме вікно тестування.

## Особливості

### ?? Тестування в реальному часі
- Не потрібно створювати справжні записи бази знань
- Миттєвий зворотний зв’язок щодо результату зіставлення
- Відображення фактичного тексту зіставлення

### ?? Симуляція інформації про Pawn
- Можна вибрати будь-якого Pawn на поточній мапі
- Автоматично включає інформацію про навички, риси та інші дані Pawn
- Точне відтворення сценарію зіставлення

### ?? Докладний журнал
- Виводить повну інформацію про зіставлення в ігровий журнал
- Містить мітки, діалоги, Pawn, відповідний текст, результати

### ?? Чітке компонування
- Верхня частина: область введення (мітки, діалоги, вибір Pawn)
- Розділювальна лінія
- Нижня частина: область відображення результатів (повністю окрема, без накладання)
- Прокручуване відображення відповідного тексту
- Розмір вікна: 650x600 пікселів

## Порядок використання

### 1. Відкрийте інструмент тестування міток

1. Відкрийте інтерфейс керування базою знань (Налаштування моду → База знань)
2. На лівій бічній панелі знайдіть кнопку **?? Тестування міток** (світло-зелена)
3. Натисніть, щоб відкрити окреме тестове вікно

### 2. Введіть тестові дані

**Тестова мітка**:
- Введіть мітку, яку хочете протестувати
- Підтримується кілька тегів, розділених комами
- Приклад: `战斗,射击,瞄准`

**Вміст діалогу**:
- Введіть текст змодельованого діалогу
- Підтримується багаторядкове введення
- Приклад: `我去练习射击技术`

**Вибір пішака** (необов’язково):
- Натисніть спадне меню, щоб вибрати пішака
- Або виберіть «Немає (лише вміст діалогу)», щоб перевірити тільки діалог
- Після вибору пішака автоматично додаються його навички, риси тощо

### 3. Виконання тесту

Натисніть кнопку **?? Тест**, і інструмент:

1. Сформує повний текст для зіставлення
   - Вміст діалогу + основна інформація про пішака + навички пішака (рівень ≥10)

2. Перевірить, чи відповідають теги

3. Відображення результатів:
   - ? **Збіг успішний** (зелений)
   - ? **Збігу немає** (червоний)

4. Виведення докладної інформації в ігровий журнал

### 4. Перегляд докладних результатів

Натисніть <kbd>F12</kbd>, щоб відкрити ігровий журнал і переглянути докладну інформацію про збіги:

```
[标签测试] 标签: 战斗,射击,瞄准
[标签测试] 对话: 我去练习射击技术
[标签测试] Pawn: 张三
[标签测试] 实际匹配文本: 我去练习射击技术 张三 女性 人类 工作狂 射击 近战 建造
[标签测试] 结果: 匹配成功
```

## Варіанти використання

### Сценарій 1: Перевірка дійсності нового тегу

**Проблема**: невідомо, чи може `[规则-战斗系统]` спрацьовувати в бойових діалогах

**Перевірка**:
1. Тег для перевірки: `规则-战斗系统`
2. Вміст діалогу: `敌人来袭，准备战斗`
3. Виберіть Pawn: будь-якого колоніста
4. Результат: ? Збігу немає

**Причина**: діалог не містить повного рядка «правила-бойова система»

**Рішення**: використовуйте `[战斗,敌人,袭击]` або `[规则-战斗,敌人]`

### Сценарій 2: хибне спрацьовування назви навички діагностики

**Проблема**: тег `[射击]` спрацьовує щоразу, навіть коли йдеться про готування

**Тестування**:
1. Тег тестування: `射击`
2. Вміст діалогу: `今天我要做饭`
3. Вибраний Pawn: Чжан Сань (стрілецька навичка, рівень 15)
4. Перегляд журналу:
   ```
   实际匹配文本: 今天我要做饭 张三 女性 人类 射击 近战 建造
   ```
5. Результат: ? Збіг знайдено

**Причина**: стрілецька навичка Чжан Саня має рівень ≥10, тому її автоматично додано до тексту для зіставлення

**Рішення**: використовуйте `[规则-射击战斗,瞄准,精准]`

### Сценарій 3: перевірка комбінованих тегів

**Проблема**: чи доречно використовувати комбінований тег `[战斗,瞄准,射击]`

**Тест 1**:
- Діалог: `我要练习瞄准`
- Pawn: немає
- Результат: ? збіг (містить «прицілювання»)

**Тест 2**:
- Діалог: `今天天气不错`
- Pawn: Чжан Сань (стрільба, рівень 15)
- Результат: ? збіг (інформація про Pawn містить «стрільба»)

**Висновок**: комбінований тег усе ще може помилково спрацьовувати через навички Pawn, тому потрібна більша точність

**Покращення**: використовувати `[战斗技巧,瞄准训练]`

## Найкращі практики

### ? Рекомендований процес тестування

1. **Спочатку протестувати сценарій без Pawn**
   - Використовувати лише вміст діалогу
   - Перевірити, чи безпосередньо пов’язаний тег із діалогом

2. **Потім протестувати сценарій із Pawn**
   - Вибрати Pawn із різними навичками
   - Перевірте, чи не відбувається хибне спрацьовування через назву навички

3. **Тестування крайніх випадків**
   - Перевірте випадок, коли в діалозі немає ключових слів тегів
   - Перевірте випадок, коли навички Pawn містять ключові слова тегів

### ? Поширені помилки

**Помилка 1**: тестування лише ідеальних сценаріїв
```
? 只测试：对话="我要射击" → 匹配
? 也要测试：对话="我要睡觉" + Pawn射击技能 → 是否误触？
```

**Помилка 2**: ігнорування впливу навичок Pawn
```
? 认为：标签 [建造] 只在讨论建造时触发
? 实际：任何建造专家（≥10级）的对话都会触发
```

**Помилка 3**: невивчення подробиць журналу
```
? 只看：? 匹配 / ? 不匹配
? 查看：实际匹配文本包含了什么
```

## Технічні деталі

### Логіка зіставлення

Інструмент використовує точно таку саму логіку зіставлення, як і бібліотека загальних знань:

```csharp
// 1. 构建匹配文本
matchText = 对话内容 + " " + Pawn名字 + " " + 性别 + " " + 种族 + 
            " " + 特性列表 + " " + 技能列表（≥10级）

// 2. 标签匹配（Any 模式）
foreach (var tag in tags)
{
    if (matchText.Contains(tag, 忽略大小写))
        return 匹配成功;
}
return 不匹配;
```

### Вміст інформації про Pawn

Під час вибору Pawn до тексту для зіставлення додається така інформація:

1. **Ім’я**: Pawn.Name.ToStringShort
2. **Стать**: чоловіча / жіноча
3. **Раса**: люди / інші раси
4. **Риси**: щонайбільше 5 тегів рис
5. **Навички**: назви всіх навичок із рівнем ≥ 10

**Приклад**:
```
张三 女性 人类 工作狂 乐观 射击 近战 建造
```

### Режим збігу

Поточний інструмент використовує **режим Any** (типово):
- збіг зараховується, якщо текст містить хоча б один тег
- відповідає режиму Any у базі знань здорового глузду

У майбутньому може з’явитися тестування режиму All.

## Усунення несправностей

### Проблема 1: результат не відповідає дійсності

**Симптом**: тест показує збіг, але в грі це не спрацьовує

**Причини**:
- запис у базі знань здорового глузду вимкнено
- запис виключено через надто низьку важливість
- Досягнуто максимальне обмеження кількості ін’єкцій

**Рішення**:
- Перевірте, чи ввімкнено здоровий глузд
- Підвищте важливість
- Збільште налаштування максимальної кількості ін’єкцій

### Проблема 2: неможливо вибрати Pawn

**Симптом**: список Pawn порожній

**Причина**:
- Гру не запущено
- На поточній мапі немає Pawn

**Рішення**:
- Завантажте збереження
- Перейдіть на ігрову мапу

### Проблема 3: інформація журналу не відображається

**Симптом**: після натискання кнопки тестування в журналі немає виводу

**Причина**:
- Вікно журналу гри не відкрито
- Фільтрування за рівнем журналу

**Рішення**:
- Натисніть <kbd>F12</kbd>, щоб відкрити журнал
- Виконайте пошук за "[Тестування тегів]"
